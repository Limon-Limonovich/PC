# Практика 04 — отказоустойчивые каналы (LACP EtherChannel)
### Сокращённая версия на 10 минут вместо 33 слайдов

**Что делаем:** 3 коммутатора 2-го уровня (2960) подключаются к коммутатору 3-го уровня (3560) **двумя** кабелями каждый; пары кабелей объединяются в **агрегированный канал (EtherChannel) по LACP**.

**Что было в оригинале:** 20 слайдов на одни и те же 3 команды, повторённые для каждой пары портов и каждого коммутатора, с «поставим `?` и выберем lacp».
**Что стало:** 4 шага — схема (2 мин) → Core (1 мин) → 3 × 2960 (3 мин) → проверка (1 мин). Все команды — в готовых файлах `configs/*.txt`.

> **Совсем коротко:** по 2 кабеля от каждого 2960 к 3560 → на 3560 `channel-group N mode active` → на каждом 2960 `channel-group 1 mode passive` → `show etherchannel summary`.

---

## 0. Итог, который должен получиться

```
                 CORE (3560-24PS)
                       │
   Fa0/1-2 ═══ Po1 ═══ Fa0/1-2  ──>  SW1 (2960)
   Fa0/3-4 ═══ Po2 ═══ Fa0/1-2  ──>  SW2 (2960)
   Fa0/5-6 ═══ Po3 ═══ Fa0/1-2  ──>  SW3 (2960)

   ═══  агрегированный канал (EtherChannel) = ДВА параллельных кабеля
```

| Канал | Порты на 3560 | Порты на 2960 | Режим 3560 / 2960 |
|---|---|---|---|
| **Po1** | Fa0/1, Fa0/2 | Fa0/1, Fa0/2 | active / passive |
| **Po2** | Fa0/3, Fa0/4 | Fa0/1, Fa0/2 | active / passive |
| **Po3** | Fa0/5, Fa0/6 | Fa0/1, Fa0/2 | active / passive |

> На каждом 2960 нумерация своя, поэтому там везде **Port-channel 1** — это нормально и так в оригинале.

---

## 1. Собрать схему (2 мин)

1. Перетащите **3560-24PS** и **3 × 2960-24TT** (Switches → 2960).
2. Соедините **Copper Straight-Through** ровно по таблице выше: по **2** кабеля на каждый 2960.
   ⚠️ Главная ошибка — попасть не в тот порт. После соединения наведите на линк и сверьте номера.
3. Переименуйте устройства: `Core`, `SW1`, `SW2`, `SW3` (клик по подписи под устройством).
4. Переключите PT в режим **Realtime** (снизу справа) — не нужен Fast Forward.

---

## 2. Настройка 3560 (Core) — 5 строк

Клик по Core → **CLI** → Enter:

```
enable
conf t
no ip domain-lookup
interface range fa0/1-2
 channel-protocol lacp
 channel-group 1 mode active
 exit
interface range fa0/3-4
 channel-protocol lacp
 channel-group 2 mode active
 exit
interface range fa0/5-6
 channel-protocol lacp
 channel-group 3 mode active
 exit
end
write memory
```

Короткий вариант (то же самое, если преподаватель не требует `channel-protocol` — протокол LACP подразумевается сам командой `mode active`):

```
en
conf t
int range fa0/1-2
 channel-group 1 mode active
 exit
int range fa0/3-4
 channel-group 2 mode active
 exit
int range fa0/5-6
 channel-group 3 mode active
 exit
end
wr
```

---

## 3. Настройка 2960 — один и тот же скрипт на всех трёх

Зайдите в CLI каждого 2960 и введите (меняется только `hostname`):

```
enable
conf t
no ip domain-lookup
hostname SW1
interface range fa0/1-2
 channel-protocol lacp
 channel-group 1 mode passive
 exit
end
write memory
```

Повторите на SW2 и SW3 (там `hostname SW2` / `SW3`). **`mode passive`** — обязательно: 3560 работает в `active`, 2960 отвечает в `passive`.

---

## 4. Проверка (1 мин) — это и есть «результат работы»

На **Core**:

```
show etherchannel summary
```

Ожидаемое (то же, что на слайде 28 оригинала):

```
Group  Port-channel  Protocol    Ports
------+-------------+-----------+--------------------------------------------
1      Po1(SU)         LACP      Fa0/1(P)  Fa0/2(P)
2      Po2(SU)         LACP      Fa0/3(P)  Fa0/4(P)
3      Po3(SU)         LACP      Fa0/5(P)  Fa0/6(P)
```

На любом **2960**:

```
show etherchannel summary

1      Po1(SU)         LACP      Fa0/1(P)  Fa0/2(P)
```

Расшифровка: `S` = Layer 2, `U` = in use, `P` = порт в канале. Если видите `Po1(SU)` и все порты `(P)` — **работа сделана**.

Доп. проверка (по желанию, 1 команда): `show lacp neighbor` — видно соседа и его Device-ID.

## 5. Бонус за 2 минуты: доказать «отказоустойчивость» (её нет в оригинале!)

Это тема работы, поэтому такой тест отлично смотрится в отчёте.

```
! 1) дать адреса (Core = .1, SW1 = .11)
Core:  conf t / interface vlan 1 / ip address 192.168.1.1 255.255.255.0 / no shut
SW1:   conf t / interface vlan 1 / ip address 192.168.1.11 255.255.255.0 / no shut
! 2) пинг
SW1# ping 192.168.1.1          → 4/4 успешно
! 3) выдернуть один кабель
SW1:  conf t / interface fa0/1 / shutdown
SW1# ping 192.168.1.1          → пинг НЕ пропадает, Po1 остаётся (SU)
! 4) вернуть
SW1:  conf t / interface fa0/1 / no shutdown
```

Вывод для отчёта: при обрыве одного физического линка агрегированный канал продолжает работать — трафик идёт по второму порту. Это и есть метод организации отказоустойчивого канала.

---

## 6. Что сдать (скриншоты)

1. Топология целиком (видно по 2 линка к каждому 2960).
2. `show etherchannel summary` на **Core** — 3 группы `(SU)`, `LACP`, порты `(P)`.
3. `show etherchannel summary` на **одном** 2960.
4. (Бонус) `ping` до и после `shutdown fa0/1`.

В отчёт — 3–5 строк текста: «Порты Fa0/1-2/3-4/5-6 коммутатора 3560 и Fa0/1-2 коммутаторов 2960 объединены в агрегированные каналы Po1–Po3 по протоколу LACP (active/passive). Каналы в состоянии SU, все порты в bundled (P). При отключении одного физического линка канал сохраняет работоспособность.»

---

## 7. Если что-то не поднялось

| Симптом | Причина / решение |
|---|---|
| `Po1(SD)` или порт `(D)` | Порт не подключён/выключен. Проверьте кабель и `no shutdown`. |
| Порт `(I)` — independent | Параметры портов не совпали: разный VLAN/скорость/duplex, либо на одной стороне `active`, а на другой `on`. Сделайте `active` / `passive`. |
| `Po1(SU)` но не все порты `(P)` | Один кабель воткнут не в тот порт — сверьте таблицу. |
| Опечатались и PT «висит» на `Translating "..."` | Ctrl+Shift+6, затем добавьте `no ip domain-lookup`. |
| Исправить группу | `int range fa0/1-2` → `no channel-group 1`, затем `channel-group 1 mode active` заново. Удалить канал: `no int port-channel 1`. |
| Ничего не появилось | Забыли `write memory` / не вышли из `conf t`; проверяйте из привилегированного режима `#`. |

## 8. Шпаргалка (всё, что нужно знать по теме)

- **EtherChannel** — объединение нескольких физических линков в один логический, чтобы получить ×N пропускную способность и резервирование (при обрыве одного линка канал жив).
- **LACP (802.3ad)** — открытый протокол агрегирования, режимы: `active` (сам ищет партнёра) и `passive` (ждёт инициативы). Пара `active`+`active` тоже работает; `passive`+`passive` — **нет**.
- **PAgP** — проприетарный Cisco аналог (`auto`/`desirable`). В этой работе не нужен.
- Требование: порты одного канала должны быть одинаковыми (VLAN, скорость, duplex) и физически идти между теми же двумя устройствами.
- Проверка: `show etherchannel summary` → `(SU)` + все порты `(P)`.
